> Этот файл читают ИИ-агенты **в первую очередь**. Его задача — за 2 минуты дать

## 1. Что это за проект (в одном абзаце)

**FindIT** — мобильное приложение (React Native + Expo) для найма в IT, которое
переосмысливает классический рекрутинг через **свайпы как в Tinder**. Цель — резко
сократить срок поиска и закрытия вакансий в условиях, когда на рынке огромный
наплыв IT-кадров, и помочь и кандидатам, и компаниям **выделиться по существу**, а
не по «красивому резюме».

## 2. Две роли — ЗАПОМНИ ИХ (источник правды)

Канонические имена ролей в продукте и базе данных — **`finder`** и **`recruiter`**.

| Роль        | Кто это                         | Что свайпает                              |
|-------------|----------------------------------|-------------------------------------------|
| `finder`    | Соискатель / IT-специалист       | **Вакансии**, которые публикуют recruiter |
| `recruiter` | Наниматель / компания / рекрутёр | **Анкеты (резюме) finder'ов**             |

Ключевая ассиметрия: **finder смотрит вакансии, recruiter смотрит людей.** Свайп
вправо — интерес, влево — пропуск. Взаимный интерес = мэтч → чат.

> ✅ **Роли унифицированы.** Канон `finder` / `recruiter` используется во всём коде.
> Единый источник типа — `lib/roles.ts` (`UserRole`, `ROLE_LABELS`, `isUserRole`),
> навигация реэкспортирует его из `navigation/types.ts`. Старые имена
> `developer`/`employer` удалены. Историческое соответствие: `developer` ≡ `finder`,
> `employer` ≡ `recruiter`.

## 3. Главные продуктовые фишки (то, чем «нагибаем» индустрию найма)

1. **Двусторонние свайпы** — быстрый первичный отбор с обеих сторон.
2. **Глубокая персонализация резюме finder'а**, а именно:
   - как специалист **работает с ИИ-агентами** (инструменты, опыт, кейсы);
   - привязка **GitHub / GitLab** → таблица последних коммитов прямо в профиле;
   - **проекты**, в которых участвовал, с возможностью их линковать.
3. **Скорость найма** как главная метрика продукта (см. `docs/PRODUCT` метрики).

## 4. Золотые правила для агента

1. **Перед любой задачей по продукту перечитай** `docs/FINDIT_PRODUCT_CONTEXT.md`.
2. Используй **только** имена ролей `finder` / `recruiter` в новом коде, тексте и схемах.
3. Не ломай разделение потоков: экран свайпа зависит от роли (люди vs вакансии).
4. Без явной задачи на бэкенд — работай на **мок-данных** (`data/`), но структура и
   тексты должны соответствовать `docs/`.
5. Секреты (`.env`) не коммить. Клиент использует только `EXPO_PUBLIC_*` и
   **publishable**-ключ Supabase (никогда `sb_secret_`).
6. После правок продуктовых решений — **обнови соответствующий файл в `docs/`**.

## 6. Быстрый старт (разработка)

```bash
npm install
# .env: скопировать из .env.example и заполнить Supabase + dev-логин
npm start            # expo start
```

Тёмная тема, палитра — в `theme/colors.ts`. В dev-сборке справа есть выезжающая
**Dev-панель** (`components/dev/DevPanel.tsx`): вход/выход и переключение роли
`finder`/`recruiter` через Supabase.
