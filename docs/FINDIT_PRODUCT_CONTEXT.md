## 1. Миссия и проблема

Сейчас на рынок IT идёт **огромный наплыв кадров**. Из-за этого:

- рекрутеры тонут в одинаковых резюме и не успевают отсматривать всех;
- сильные специалисты теряются в массе и не могут выделиться по существу;
- сроки найма растягиваются на недели, хотя решение часто можно принять за минуты.

**FindIT переосмысливает поток найма целиком.** Вместо длинных откликов и переписок
— быстрый взаимный отбор свайпами и резюме, в котором видно **реальную работу**
специалиста (код, проекты, опыт с ИИ-агентами), а не только список ключевых слов.

**Девиз продукта:** максимально сократить срок поиска сотрудника и дать сильным
специалистам способ выделиться содержанием и оформлением.

## 2. Роли (только `finder` / `recruiter`)

В продукте, коде и базе данных есть **ровно две** роли: `finder` и `recruiter`.
Других ролей нет. Имена везде одинаковые: тип `UserRole` (`lib/roles.ts`),
навигация, UI, enum `user_role` в Postgres.

### 2.1 `finder` — соискатель / IT-специалист

- Регистрируется как соискатель.
- Заполняет **детально персонализированное резюме** (см. раздел 4).
- **Свайпает вакансии**, которые публикуют recruiter'ы (а не другие резюме).
- Свайп вправо по вакансии — отклик/интерес, влево — пропуск.
- Видит свои мэтчи и чаты с компаниями.

### 2.2 `recruiter` — наниматель / компания / рекрутёр

- Регистрируется как recruiter (наниматель / компания).
- Заполняет данные компании и публикует **вакансии**.
- **Свайпает анкеты finder'ов** (резюме) — вправо «интересен», влево «пропуск».
- Видит мэтчи и переписки с откликнувшимися finder'ами.

### 2.3 Ключевая ассиметрия (запомнить)

> **finder смотрит вакансии. recruiter смотрит людей.**
> Главный экран свайпа меняет контент в зависимости от роли.
> Взаимный свайп вправо = **мэтч** → открывается чат.

## 3. Ключевые сценарии (happy path)

**Finder:**
1. Онбординг → выбор роли `finder` («Я специалист»).
2. Регистрация → заполнение резюме (мастер шагов).
3. Лента **вакансий**: свайпы. Тап по карточке → детальная вакансия + компания.
4. Мэтч с вакансией → чат с recruiter'ом.

**Recruiter:**
1. Онбординг → выбор роли `recruiter` («Я рекрутер»).
2. Регистрация → данные компании → публикация вакансии.
3. Лента **анкет finder'ов**: свайпы. Тап → детальное резюме (код, проекты, ИИ-опыт).
4. Мэтч с finder'ом → чат.

---

## 4. Персонализация резюме finder'а — главная фишка

Резюме должно показывать **реальную работу**, а не только ключевые слова. Минимально:

1. **Базовое**: имя, фото, заголовок (позиция/грейд), стек-теги, опыт (лет), желаемая
   позиция, зарплатные ожидания, локация/формат работы, «о себе».
2. **Опыт работы с ИИ-агентами** — отдельная секция: какими инструментами/агентами
   пользуется (напр. Cursor, Claude Code, Copilot и т.п.), как встраивает их в
   рабочий процесс, конкретные кейсы/результаты. Это сознательный дифференциатор
   продукта в эпоху ИИ-разработки.
3. **Git** (GitHub / GitLab по ссылке):
   - finder вставляет URL — провайдер и иконка определяются автоматически;
   - опционально включает **грид коммитов** (heatmap + таблица последних коммитов);
   - позже: подтяжка коммитов/heatmap из API без токена в клиенте.
4. **Проекты**: список проектов, в которых участвовал, с описанием роли и вклада;
   проекты можно **линковать** (URL на репозиторий/демо/кейс).

> Детали хранения этих данных — см. [`DATA_MODEL.md`](./DATA_MODEL.md)
> (таблицы `finder_profiles`, `projects`, `vcs_accounts`, `vcs_commits`).

## 5. Вакансия recruiter'а (что свайпает finder)

Минимальный состав карточки вакансии: название позиции, компания, грейд/уровень,
стек, вилка зарплаты, формат (офис/гибрид/удалёнка) и локация, краткое описание,
1–2 якорных факта (продукт, команда, технологии). Детальный экран — полное описание
+ карточка компании.

---

## 6. Ключевые экраны (минимальный набор)

1. **Онбординг / выбор роли** — ценность продукта → `finder` («Я специалист») / `recruiter` («Я рекрутер»).
2. **Регистрация / вход** — email + пароль/OTP; роль явная. Состояния: загрузка, ошибка.
3. **Мастер заполнения профиля** (многошаговый, с прогрессом «Шаг N из M»):
   - finder: стек, опыт, позиция, зарплата, формат, секция ИИ-опыта, Git (ссылка +
     привязка GitHub/GitLab), проекты, «о себе», фото;
   - recruiter: компания, индустрия, размер, контакт; затем мастер создания вакансии.
4. **Главный свайп** (контент зависит от роли):
   - recruiter → карточки **анкет finder'ов**;
   - finder → карточки **вакансий**.
   Жесты влево/вправо + кнопки-дубли для доступности; фильтры (локация/позиция).
5. **Детальная карточка** — полное резюме (грид Git-активности, таблица коммитов, проекты)
   или полная вакансия + компания.
6. **Мэтчи / чаты** — список диалогов после взаимного интереса.
7. **Профиль** — это **своё резюме** (ИИ-инструменты, Git, стек, ожидания, опыт
   для finder; компания и контакт для recruiter) в стеклянных секциях. LinkedIn-style
   edit по кирпичу (карандаш → сохранить/отмена). Шапка (фото/имя): в PreEdit тап
   открывает дропдаун «Изменить имя» (инлайн-инпут) / «Изменить фото» (picker);
   желаемый грейд finder'а показывается под именем, правится в секции **Ожидания**.
   Внизу меню: **Настройки** (язык, выход, выбор темы карточки свайпа), **Оценки**,
   у recruiter — **Мои вакансии**. Оформление карточки в ленте — библиотека тем
   (Path A) + JSON-заготовка.

## 7. Навигация (логически)

- Стек авторизации (Welcome → Register) до входа в основное приложение.
- Основной таб-навигатор: **Свайп → Чаты → Профиль** (текущая реализация).
- Из карточки свайпа — переход на детальный экран (резюме/вакансия).
- Редактирование профиля — LinkedIn-style по секциям на хабе; мастер регистрации
  остаётся для онбординга. Настройки / Оценки / Мои вакансии — вложенный стек.

> Текущая реализация навигации — см. [`ARCHITECTURE.md`](./ARCHITECTURE.md).

## 8. Тон и UX-принципы

- **Быстро и по делу:** на карточке свайпа минимум текста, детали — на детальном экране.
- **Содержание важнее оформления:** код, проекты и реальный опыт на первом плане.
- **Симметрия ролей:** оба пользователя чувствуют, что отбор взаимный и честный.
- **Доступность:** крупные зоны нажатия, контраст, свайпы продублированы кнопками.

## 9. Терминология (держать единообразно)

| Термин | Смысл |
|--------|-------|
| finder | Соискатель / IT-специалист. Одна из двух ролей (`UserRole`). |
| recruiter | Наниматель / компания. Вторая роль (`UserRole`). Других ролей нет. |
| Анкета / резюме | Профиль finder'а |
| Вакансия | Позиция, опубликованная recruiter'ом |
| Свайп вправо | Интерес / отклик |
| Свайп влево | Пропуск |
| Мэтч | Взаимный свайп вправо → открывает чат |
